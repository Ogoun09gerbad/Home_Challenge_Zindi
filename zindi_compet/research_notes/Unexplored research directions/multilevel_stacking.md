# Multi-level stacking (meta-learning on OOF) — literature and competition write-ups

Scope: true 2-level stacking (meta-model trained on the out-of-fold predictions of the base models, optionally combined with the original features), NOT fixed-weight blending nor Caruana-style hill-climbing/ensemble selection (already covered and already tested negatively in this project).

## Q1 — Does 2-level stacking (non-linear meta-model or one with interactions) document a gain beyond an already-optimized linear/greedy blend, and of what order of magnitude?

### Key conclusion
Documented gains of stacking over an already-optimized blend/selection exist, but are consistently described as conditional on the **diversity** of the base models (low error correlation); when the base models are few and correlated — exactly the case here (3 additive probit models on an additive signal with 15 features) — the literature and practitioners converge on "zero or marginal gain", with an order of magnitude rarely quantified precisely. A distinct avenue, less covered by the blend already tested, is **feature-weighted linear stacking (FWLS)**, which varies the blend weight as a function of features (not just a single fixed global weight), and which has a documented track record of gains (Netflix Prize) even with relatively similar base models.

### Sourced findings
- Founding paper of Feature-Weighted Linear Stacking (FWLS), Sill, Takacs, Mackey, Lin (2009): method derived from the 2nd-place Netflix Prize solution; the blend is linear but the base-model weights are themselves linear functions of "meta-features" (so the weight varies across regions of the feature space, rather than being a constant global weight); the authors report clear accuracy gains over standard linear stacking on the Netflix collaborative filtering data — but the search could not extract an exact gain figure. — [Feature-Weighted Linear Stacking (arXiv 0911.0460)](https://www.arxiv.org/pdf/0911.0460)
- More recent extension: NN-Stacking (Coscrato, Inácio, Izbicki) generalizes FWLS by using a neural network to learn how the weights vary with the input features. — [NN-Stacking (arXiv 1906.09735)](https://ar5iv.labs.arxiv.org/html/1906.09735)
- Controlled experiment (synthetic, binary classification): with diverse base models, stacking beats the best single model by about 1 point; with 3 mutually correlated tree ensembles, the stacked result is within noise of the best single model (0.835 vs 0.834) — the author attributes this to the models agreeing too much to leave anything for the meta-model to exploit. — [Does Stacking Beat Your Best Model?](https://towardsdatascience.com/does-stacking-beat-your-best-model/)
- Theoretical argument cited in connection with this experiment: an ensemble's variance reduction follows a (1-ρ̄)σ²/M term (ρ̄ = mean error correlation), and the ρ̄σ² limit is reached quickly when ρ̄ is already high — so adding levels/models barely helps once correlation is strong. (Attribution uncertain between the source above and a related theoretical article found in the same search; treat as a qualitative argument rather than a validated figure.)
- Practitioner advice (vecstack GitHub thread): "quality is not just about the score but also about low correlation of predictions"; "a stack of 3 good, weakly correlated models can beat a stack of 30 highly correlated models"; recommendation to always try simple averaging first, since stacking is sometimes unnecessary. — [vecstack issue #41](https://github.com/vecxoz/vecstack/issues/41)
- Otto Group Product Classification (winner): stacking of 30+ models whose outputs feed 3 meta-classifiers (XGBoost, neural network, AdaBoost) — a concrete example of a non-linear meta-learner used in 1st place, but on a much larger and more diverse model library than 3 models. — [KDnuggets — Ensemble Learning](https://www.kdnuggets.com/2017/09/ensemble-learning-improve-machine-learning-results.html/2)
- Reported quantified gain (secondary source, KDD Cup 2014): a model reportedly went from about 0.605 AUC to about 0.625 AUC thanks to stacking — an order of magnitude of +0.02 AUC, but the context (number and diversity of base models) is not specified in the summary found. — [Using Ensembles in Kaggle Data Science Competitions – Part 3](https://www.kdnuggets.com/2015/06/ensembles-kaggle-data-science-competition-p3.html)
- Documented counter-example where deeper stacking **does not help** (or is slightly worse): in a StackNet GitHub thread about the Zillow competition (noisy real-estate regression, weak signal — a profile close to the present case), a user reports that StackNet alone reaches ~0.0647 on the LB while a more classic 2-level stack reaches ~0.0645 (lower = better here) — so the more complex stacking was worse. — [kaz-Anova/StackNet issue #47](https://github.com/kaz-Anova/StackNet/issues/47)
- Recent winning solution with 3-level stacking (Chris Deotte, Kaggle Grandmaster, Kaggle Playground April 2025, regression): 75 level-1 models selected from ~500 trials, whose OOFs feed a level 2 (GBDT + NN) chosen by forward feature selection, with original features optionally included at level 2; level 3 = weighted average of the level-2 outputs. CV RMSE 11.54, private LB RMSE 11.44. **No reference score (single model or simple blend) is given in the article** — so it is impossible to isolate the gain specifically contributed by multi-level stacking in this case. — [NVIDIA Developer Blog — Grandmaster Pro-Tip](https://developer.nvidia.com/blog/grandmaster-pro-tip-winning-first-place-in-a-kaggle-competition-with-stacking-using-cuml/)
- AutoGluon (academic paper, AutoML): multi-layer stacking, combined with bagging and a diverse model library, is presented as making better use of the allotted training time than searching for the best single model; tested on 50 Kaggle/OpenML tasks, AutoGluon even outperforms the post-hoc combination of all its competitors. AutoGluon 1.0 reports a 99% win rate vs LightGBM and 100% vs XGBoost on 1040 tasks of the OpenML AutoML Benchmark — but these are aggregate figures (bagging + stacking + several model families), not an isolated measurement of the contribution of multi-layer stacking alone. — [AutoGluon-Tabular (arXiv 2003.06505)](https://arxiv.org/pdf/2003.06505)
- Guidance directly applicable to the case with few base models: "stacking generally does not pay off on small datasets because each layer consumes data and the meta-model weights end up fitting noise; for limited history, a fixed average of two or three diverse models is often the most robust choice"; and "blending/stacking similar models often brings little or no gain, the benefit depending on whether the base models make errors of a different nature". — [LuxAlgo — Model Stacking](https://www.luxalgo.com/library/concept/model-stacking.md)
- Academic comparison of stacking vs best-model selection by CV (Džeroski & Ženko, 2002): several state-of-the-art stacking methods at best only tie with simply selecting the best classifier by cross-validation; the authors propose a stacking variant (multi-response model trees) that beats both, suggesting that the choice of meta-learner is decisive and that "generic" stacking (simple logistic regression on OOF) has no guaranteed superiority over the Caruana-style selection already tested in this project. — [Stacking with multi-response model trees](https://kt.ijs.si/bernard/publication/dzeroski-2002-stacking/)

### Inferences
- The exact profile of the current pipeline (3 additive models with a probit link, LightGBM/CatBoost/GAM, already very similar because they all approximate the same additive score + known Gaussian noise) matches precisely the scenario in which the literature and practitioners report the smallest, or even negative, stacking gain: few base models, high error correlation. The sources document **no case where non-linear stacking "rescued" a situation in which the linear/greedy blend had saturated with so few and such correlated models** — the evidence found points rather in the opposite direction (StackNet/Zillow, towardsdatascience synthetic experiment, vecstack advice).
- The most promising avenue that is **not** covered by the fixed-weight blend already tested is FWLS (blend weights varying with meta-features/original features, rather than a single global weight): it captures a different mechanism (heterogeneity of the optimal weight across regions of the feature space) that neither fixed-weight blending nor greedy hill-climbing can capture, since both methods search for a constant global weight. This is the avenue most likely to bring a real gain that is not redundant with what has already been tested — but no quantified gain magnitude could be found for a case with 2-3 base models.
- With only 3 base models (or even the 2-model blend already retained), a logistic-regression meta-model on the OOFs alone reduces algebraically to a form very close to a linear blend (a logistic regression on 2-3 nearly collinear probit scores has almost no extra degrees of freedom to exploit compared to the continuous weight search already performed) — which explains why the literature reports no distinct gain for this specific case.

### Gaps
- No source precisely quantifies the gain of FWLS outside the Netflix Prize setting (no magnitude transferable to an AUC/logloss tabular binary classification context).
- No Kaggle write-up from 2024-2026 was found that explicitly documents a "blend saturates with correlated models → non-linear stacking still finds a gain" case on a pool of comparable size (≤5 models). The multi-level stacking write-ups found (Deotte, Otto Group) all involve libraries of tens to hundreds of diverse models, not 2-3 already-similar models.
- No figure was found explicitly linking the order of magnitude of the stacking gain to the Zindi composite metric (0.4×AUC + 0.6×(1-logloss/0.595)) used here — no source addresses this specific metric.

## Q2 — Competition precedents where stacking solved a similar problem (few base models already very similar/correlated, saturating linear blend, non-linear stacking finding a gain)

### Key conclusion
No direct precedent was found matching this pattern exactly (few models, high correlation, saturated blend, non-linear stacking unlocking a gain). The available precedents point in the opposite direction: on small and/or correlated pools, more complex stacking at best ties, and in at least one documented case (Zillow/StackNet) does worse than simpler stacking.

### Sourced findings
- StackNet thread (Zillow, a real-estate regression competition with a weak, noisy signal, a profile comparable to the liquidity challenge studied here): 3+-level stacking (StackNet) reaches ~0.0647 on the LB, simpler 2-level stacking reaches ~0.0645 (better) — the extra complexity of the upper level did not help. — [kaz-Anova/StackNet issue #47](https://github.com/kaz-Anova/StackNet/issues/47)
- Controlled experiment (towardsdatascience): with correlated models (3 variants of tree ensembles), the gain of stacking over the best single model is within statistical noise (0.835 vs 0.834). — [Does Stacking Beat Your Best Model?](https://towardsdatascience.com/does-stacking-beat-your-best-model/)
- Academic comparison (Džeroski & Ženko 2002): the state-of-the-art stacking methods of the time do not beat simply selecting the best model by CV, except for a specially designed variant (multi-response model trees). — [Stacking with multi-response model trees](https://kt.ijs.si/bernard/publication/dzeroski-2002-stacking/)
- All successful stacking write-ups found (Otto Group, Deotte/Kaggle Playground April 2025) involve tens to hundreds of diverse base models (varied algorithm families: GBDT, NN, linear models, etc.), not a small pool of already-similar models — so this is not evidence transferable to the present case (3 models, all additive/probit). — [NVIDIA Developer Blog](https://developer.nvidia.com/blog/grandmaster-pro-tip-winning-first-place-in-a-kaggle-competition-with-stacking-using-cuml/) ; [KDnuggets](https://www.kdnuggets.com/2017/09/ensemble-learning-improve-machine-learning-results.html/2)

### Inferences
- The absence of a positive precedent for this specific pattern, combined with the convergence of counter-examples (StackNet/Zillow, synthetic experiment, error-correlation theory), constitutes reasonably solid evidence that generic 2-level stacking (meta-model on the OOFs of the 3 existing models, without adding extra base models or original features) has a low probability of bringing a measurable gain on this pipeline — consistent with the negative result already obtained with hill-climbing.
- If a gain is to be sought via stacking, the literature suggests that the non-linearity of the meta-model is not the missing lever, but rather either (a) adding truly diverse base models (different algorithm families, not variants of the same additive probit model) before stacking, or (b) an FWLS that varies the blend weight according to the original features (see Q1) — which is a structurally different avenue from the generic stacking investigated here.

### Gaps
- Non-exhaustive search of Kaggle forums specific to competitions with an exact-quota synthetic generator (a profile close to the Zindi challenge studied) — no thread found specifically addressing this type of generator together with stacking.
- No data found on Zindi competitions (as opposed to Kaggle) addressing 2-level stacking on a small pool of correlated models.

## Q3 — Does the risk of stacking overfitting on the OOFs have documented solutions (e.g. second-level OOF via nested CV) that change the conclusion?

### Key conclusion
Yes, solutions are well documented (strict OOF to avoid leakage, nested/repeated CV to honestly evaluate the whole pipeline), but they are **validation** and **optimistic-bias prevention** safeguards, not **performance** levers: they do not change the substantive conclusion if the additional signal exploitable by a meta-model is genuinely absent (the likely case here, see Q1/Q2) — they only prevent wrongly concluding that there is a gain when it is actually overfitting on the OOF folds.

### Sourced findings
- Standard anti-leakage rule (AutoGluon): higher-level models must only be trained on the OOF predictions of lower-level models, never on in-fold predictions. — [AutoGluon-Tabular (arXiv 2003.06505)](https://arxiv.org/pdf/2003.06505)
- Stacking with k-fold bagging yields an OOF prediction for every training row for every model (each example is out-of-fold for at least one bagged copy of each model). — [AutoGluon-Tabular (arXiv 2003.06505)](https://arxiv.org/pdf/2003.06505)
- Nested CV separates the outer loop (evaluation) from the inner loop (tuning), which corrects the optimistic bias obtained when tuning and evaluating on the same folds; on small, noisy datasets, this optimism can exceed several percentage points of accuracy. — aggregated search, no single authoritative source found for this exact figure; see general discussion of nested CV.
- Recommendation of a simple meta-learner to limit the overfitting risk of the stacking layer: a simple meta-learner reduces this risk; more complex meta-learners (regularized model, another tree) are only justified when there are many base models — which argues against using a GBM as the meta-model here, since the base pool is only 2-3 models.
- Recent academic application (2026, preprint not independently verified): a "leak-free" stacking framework with per-architecture calibration, which trains each base model on the other folds and predicts the held-out fold to obtain one OOF prediction per example and per architecture, then combines these OOFs — illustrates the standard mechanics applied to a new domain (image segmentation), but does not address the question of net performance gain. — [Leak-Free Cross-Validated Stacking (arXiv 2607.25367)](https://arxiv.org/pdf/2607.25367) — **caution: preprint dated 2026, not independently verified, to be treated as a methodological lead rather than a validated result.**

### Inferences
- Applying nested (or repeated) CV to stacking here would only give a more honest estimate of a gain which, according to Q1/Q2, is probably zero or marginal with only 3 correlated base models — so it is not a solution that would "unlock" a hidden gain, but a validation tool that would avoid relying on an illusory gain measured with plain 5-fold (consistent with the fact that hill-climbing had already been validated with nested 5-fold and found nothing).
- If stacking were to be tested anyway, the literature explicitly recommends a simple meta-learner (regularized logistic/probit regression) rather than a GBM, precisely because the base pool is small (2-3 models) — a GBM as a meta-model on only 2-3 features (the OOFs) carries an overfitting risk disproportionate to the expected gain.

### Gaps
- No source provides a single, complete protocol combining base hyperparameter tuning + stacking + repeated nested CV with a quantification of the corrected optimism in a comparable tabular binary classification context (40,000 rows, 15 features, additive signal + Gaussian noise, exact quota).
- The figure "several percentage points of optimism on small noisy datasets" has no clearly citable single source found in this search; to be verified separately if this figure is to be used in a final report.
